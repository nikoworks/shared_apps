# TaskBoard 要件定義

更新日: 2026-06-11

## 1. 目的

TaskBoardは、NikoWorksの進行管理において、各メンバーの当日作業、未完了タスクの繰り越し、プロジェクト進行、確認事項を一元管理するためのアプリである。

スプレッドシートやChatworkだけでは見えにくかった次の問題を解決する。

- 誰が今日何をやるかが見えない
- 未完了タスクが埋もれる
- プロジェクトごとの進行状況が見えない
- Chatwork上のタスクが管理データとして残らない
- プロジェクト名やクライアント名の表記ゆれが増える
- 確認事項と作業タスクが混ざる

## 2. 基本方針

### 今日のタスクの定義

「今日のタスク」は、今日登録されたタスクではなく、今日中に終わらせるべきタスクである。

表示対象:

- 今日の日付で登録された未完了タスク
- 昨日以前に終わらず、作業日が今日へ移動された未完了タスク
- 未来日で登録され、その日になったタスク

完了済みタスクは通常表示から外すが、履歴として保持する。

### プロジェクトの定義

プロジェクトは、案件・納品物・月号・キャンペーンなど、進行を管理する単位である。

タスクは原則として必ずプロジェクトに紐付く。

未経験案件や未整理案件では、最初はフェーズなしでタスクを積み上げてもよい。

### フェーズの定義

フェーズは、プロジェクト内の工程である。

例:

- 企画
- 制作
- 確認
- 修正
- 提出
- 納品

フェーズは必須ではない。管理上必要になった時点で追加する。

### 確認の定義

確認は、進行に影響する判断・依頼・質問・共有である。

個人的な作業相談はTaskBoardの確認には含めない。

## 3. 利用者

| 利用者 | 主な役割 |
|---|---|
| 佐久間さん | 全体管理、プロジェクト整理、データ整理、最終確認 |
| 窓口担当 | 案件の進行責任、プロジェクト作成、納品日確認 |
| 発起人 | 新規案件の起点、プロジェクト作成 |
| メンバー | タスク入力、完了チェック、進行確認への対応 |

## 4. 主要機能

### タスク管理

必要機能:

- タスク登録
- 一括入力
- Chatwork取り込み
- 担当者別表示
- プロジェクト別表示
- 日付範囲表示
- 完了チェック
- 完了済み表示切替
- 未完了タスクの今日への移動
- 予定時間の0.25時間単位入力
- 備考入力
- 進行確認の登録

### Chatwork取り込み

TASK部屋から `#task` / `#ask` を含む投稿を取得する。

要件:

- 手動ボタンで取得できる
- 同じChatworkメッセージを二重取り込みしない
- 投稿者のChatworkアカウントIDから担当者を判定する
- 未登録メンバーの投稿は取り込まず警告する
- `,` と `/` の区切りに対応する
- 日付指定に対応する
- プロジェクト名不明は確認待ちにする
- 取得後は「全員、最新に更新してください」と案内する

### プロジェクト管理

必要機能:

- プロジェクト作成
- プロジェクト編集
- プロジェクト完了
- 完了プロジェクトの通常非表示
- クライアントで絞り込み
- 窓口担当で絞り込み
- 登録者の記録
- 納品日必須扱い
- 開始日管理
- 案件流入元の記録
- 案件流入元詳細の記録
- 定期案件名の管理
- プロジェクト種別管理
- フェーズ管理
- プロジェクトに紐付くタスク一覧表示

プロジェクト作成権限の運用:

- 佐久間さん
- 窓口担当
- 発起人

上記以外のメンバーは、原則として既存プロジェクトを選ぶ。

### クライアント管理

現状、クライアントは独立テーブルではなく、プロジェクトの `clientName` として保存される。

必要機能:

- 既存クライアントのプルダウン選択
- 新規クライアント追加
- 表記ゆれの統合
- 統合時に、対象プロジェクトのクライアント名を一括置換

### データ整理

目的:

仕様変更やChatwork取り込みによって発生した不整合を、管理画面から整理する。

対象:

- 未紐付け・確認待ちタスク
- 仮プロジェクト
- クライアント名の表記ゆれ
- 繰り越し不整合
- フェーズ不整合
- 不足情報プロジェクト
- 重複タスク

要件:

- 重複タスクは、同じ担当者・同じ日付・同じ内容・同じ確認元のものを検出する
- 重複表示は1行にまとめる
- 正式プロジェクトへ紐付ける際、同じ重複グループもまとめて紐付けられる
- 削除ではなく、まずは統合・紐付け・アーカイブで整理する

### ガント

目的:

プロジェクト全体の流れを俯瞰し、クライアント別・定期案件別・担当者別に進行を確認する。

要件:

- クライアント別表示
- 定期案件別表示
- 窓口担当別表示
- 担当者別表示
- プロジェクト種別別表示
- 期間指定
- 日付ヘッダー固定
- 横スクロール
- プロジェクト単位のまとまり表示
- フェーズ行のグループ表示
- 遅れ気味のプロジェクト・フェーズの警告表示
- 納品日未設定の警告表示
- 完了プロジェクトの非表示

## 5. 画面要件

### タスク画面

表示内容:

- 担当者ごとのタスク
- 日付チップ
- 繰り越しラベル
- プロジェクト名
- クライアント名
- 予定時間
- 備考
- 確認ありラベル

並び順:

1. 古い繰り越しタスク
2. 昨日以前のタスク
3. 今日のタスク
4. 未来日のタスク

日付表示は、利用者が直感的にわかるように「今日」「昨日」「5日前」「6/12」などで表示する。

### プロジェクト画面

表示内容:

- クライアント名
- プロジェクト名
- 案件流入元
- 定期案件名
- 窓口担当
- 登録者
- 納品日
- 開始日
- フェーズ
- 紐付くタスク数
- 不足情報

フィルター:

- クライアント
- 窓口担当
- プロジェクト種別
- 案件流入元
- 進行状態

### 案件流入元管理

目的:

どのチャネルから来た案件が多いかを把握し、今後強化すべき営業・集客チャネルの判断材料にする。

プロジェクトごとに、案件流入元と流入元詳細を記録する。

案件流入元の選択肢:

- 自社開発
- LPからの問い合わせ
- 自社HPからの問い合わせ
- 既存クライアントからの紹介
- 代理店からの案件
- メディアレーダー
- 既存クライアントからの追加依頼
- 営業・直接提案
- その他

流入元詳細には、フォーム名、紹介元、媒体名、資料名、代理店名、営業経路など、後から分析に使える具体情報を残す。

### データ整理画面

表示内容:

- 未紐付けタスク数
- 仮プロジェクト数
- クライアント名数
- 繰り越し不整合数
- 不足情報プロジェクト数

操作:

- 未紐付けタスクを正式プロジェクトに紐付け
- 仮プロジェクトを正式プロジェクトへ統合
- クライアント表記ゆれを統合
- 不整合を修正
- プロジェクト・タスクを編集
- バックアップ取得
- 最新データ取得

## 6. データ要件

Supabase上では `taskboard_data` という1テーブルにJSONとして保存する。

JSON内の主要データ:

- `members`
- `projects`
- `tasks`
- `asks`
- `templates`
- `chatworkImports`
- `projectReviews`
- `meta`

詳細は `DATABASE_SCHEMA.md` を参照。

## 7. 保存と同期

保存方式:

- 各操作後、ブラウザ内データを更新する
- Supabaseへ自動保存する
- 保存失敗時は警告を出す

同期方式:

- 他の人の画面は自動では即時更新されない
- 最新状態を見るには「最新に更新」を押す
- Chatwork取得後は、全員に更新を促す

将来的な自動同期:

- リアルタイム同期を導入する場合は、有料プランや実装コストを検討する
- 現時点では手動更新で運用する

## 8. 環境変数

Vercelに設定する環境変数:

| 変数名 | 内容 |
|---|---|
| `CHATWORK_API_TOKEN` | Chatwork APIトークン |
| `CHATWORK_ROOM_ID` | TASK部屋のルームID |
| `TASKBOARD_IMPORT_KEY` | 取り込み確認用キー |

Supabase接続情報は、公開してよいanon keyのみをフロント側で使う。

秘密情報はGitHubやアプリ画面に貼らない。

## 9. 現在の注意点

- 過去仕様で作成された仮プロジェクトが残っている
- プロジェクト未紐付けタスクが多く残っている
- クライアント名の表記ゆれがある
- 完了チェック後に、他端末では最新更新が必要
- データ整理画面で一度クリアな状態に整える必要がある

## 10. 今後の改善候補

- 重複タスクの自動統合
- プロジェクト候補の精度向上
- クライアントマスタの独立管理
- 定期案件テンプレートの整備
- フェーズごとの実行条件管理
- ガント上でのフェーズ依存関係表示
- 完了タスクの月次実績レポート
- Chatworkへの確認依頼自動送信
- リアルタイム同期
