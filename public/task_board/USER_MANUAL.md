# TaskBoard 運用マニュアル

## 1. 毎日の基本運用

各メンバーは、自分用URLからTaskBoardを開きます。

自分用URLを開くと、最初から自分のタスクだけが表示されます。

全体の進行状況を見たいときは、左メニューの「プロジェクト」を開きます。

## 2. 個人URLのコピー

管理者は「設定」→「メンバー管理」を開きます。

各メンバーの行にある「個人URL」ボタンを押すと、その人専用のURLをコピーできます。

## 3. タスクの一括入力

「今日のタスク」→「一括入力」から、Chatworkやメールで送られてきた内容を貼り付けます。

Chatwork連携を設定している場合、管理者は全メンバー表示の状態で「Chatworkから取得」にルームIDを入れて「Chatwork取得」を押します。

個人URLで開いている画面には、Chatwork取得欄は表示されません。

最新100件の中から `#task` / `#ask` を含む投稿だけが入力欄に入ります。

取得後は、必ず確認画面で内容を見てから登録します。

Chatwork連携に必要なVercel環境変数:

- `CHATWORK_API_TOKEN`: ChatworkのAPIトークン
- `TASKBOARD_IMPORT_KEY`: 取り込み用の合言葉。任意ですが設定推奨
- `CHATWORK_ROOM_ID`: 既定のルームID。任意

APIトークンはGitHubやアプリ画面には貼りません。

基本フォーマット:

```text
6月2日
#task
プロジェクト名, タスク, 時間, 内容, 備考
A社サイト制作, トップページデザイン, 1, 画像差し替え
+, 画像制作, 1, バナー用画像の制作
?, 原稿確認, 0.25, プロジェクト名が不明
```

ルール:

- 日付は `6月2日`、`2026/06/02`、`6/2` のように、`#task` の前に書けます。
- 日付を書かない場合は、取り込み日または画面で選んでいる日付のタスクになります。
- 1行に1タスクを書きます。
- 先頭がプロジェクト名なら、そのプロジェクトのタスクになります。原則として、アプリにある既存プロジェクト名を使います。
- 先頭が `+` または `＋` なら、直前と同じプロジェクトになります。
- 先頭が `?` または `？` なら、プロジェクト未設定タスクになります。新規プロジェクトか判断できない場合に使います。
- 区切り文字は `,` または `/` が使えます。
- 時間は `1`、`0.25`、`0.5`、`2` のように書きます。
- 備考には、作業メモ、補足、引き継ぎを書けます。

## 4. プロジェクト未設定がある場合

一括入力で「確認する」を押したとき、プロジェクト未設定タスクがあると警告が出ます。

「Chatwork文をコピー」を押すと、本人に送る修正依頼文をコピーできます。

本人は自分用URLからTaskBoardを開き、該当タスクの「編集」からプロジェクトを選び直します。

## 5. プロジェクト名が似ている場合

Chatworkから取り込んだプロジェクト名が既存プロジェクトと完全一致しない場合、TaskBoardは似ているプロジェクトを探します。

ただし、「プロジェクト確認待ち」が増えすぎると管理負荷が上がるため、原則は入力時に既存プロジェクト名を使って解決します。

メンバーは、勝手に新しいプロジェクト名を作らず、まず既存プロジェクト名を選びます。

新規案件と思われる場合は、次のどちらかで処理します。

- 発起人・窓口担当・佐久間さんが、先にアプリで新規プロジェクトを作成する
- それ以外のメンバーは `?` を使い、備考に「新規案件かも」と書く

似ているプロジェクトが見つかった場合だけ、Chatworkに「プロジェクト確認URL」が送られます。

URLを開くと、専用の「プロジェクト確認」画面が表示されます。

確認画面では、対象タスクごとに次の選択ができます。

- 既存の類似プロジェクトに紐付ける
- 新規プロジェクトとして作成する
- 佐久間さん確認に回す

保存すると、対象タスクが選んだプロジェクトにまとめて紐付きます。

新規プロジェクトとして作成した場合は、仮プロジェクトとして登録されます。あとでプロジェクト画面から納品日や担当者を整えます。

## 6. 新規プロジェクトを増やさないルール

プロジェクトの乱立を防ぐため、新規プロジェクトを作れる人を限定します。

新規プロジェクトを作成してよい人:

- 佐久間さん
- その案件の窓口担当
- その案件の発起人

それ以外のメンバーは、原則として既存プロジェクトを選びます。

既存プロジェクトが見つからない場合は、勝手に新規名を作らず、次のように投稿します。

```text
#task
?, タスク名, 時間, 内容, 新規案件かも
```

管理者または窓口担当が確認し、必要であれば正式な新規プロジェクトを作成します。

プロジェクト名の入力ミスを減らすため、プロジェクト名はできるだけ手入力せず、アプリ上の候補から選びます。

## 7. 進行確認の入力

タスクと同じ投稿の中に、進行に関わる確認も入れられます。

タスク編集画面からも、そのタスクに紐づく「進行確認」を登録できます。

ここに入れるのは、次の工程、納期、判断、担当者への受け渡しに影響するものだけです。

個人的な作業上の質問や相談は、TaskBoardには残さず、本人同士で直接確認します。

入力する項目は次の3つです。

- 誰に
- いつまでに
- 内容

登録すると、宛先の個人ページに「あなた宛の進行確認」として表示されます。

タスク一覧には「確認あり」と表示されます。

フォーマット:

```text
#ask
種別, 宛先, 内容, 関連プロジェクト, 期限
確認, 田中さん, A社LPの画像方向を確認してください, A社サイト制作, 今日中
確認, 佐藤さん, B社パンフを校正工程へ進めてよいか確認してください, B社パンフ, 5/29
確認, 鈴木さん, 広告入稿に進めてよいか確認してください, A社広告, 今日中
共有, 全員, クライアントから素材が届きました, A社サイト制作, -
```

種別:

- `確認`: 次工程へ進めてよいか判断してほしいこと
- `依頼`: 進行に必要な対応をお願いしたいこと
- `質問`: 進行が止まるため答えが必要なこと
- `共有`: 知っておいてほしいこと

## 8. タスクと進行確認を同時に送る例

```text
6月2日
#task
A社サイト制作, トップページデザイン, 1, 画像差し替え
+, 画像制作, 1, バナー用画像の制作

#ask
確認, 田中さん, A社LPの画像方向を確認してください, A社サイト制作, 今日中
確認, 鈴木さん, 広告入稿に進めてよいか確認してください, A社広告, 今日中
```

## 9. 個人ページでの見え方

個人ページには、次の順番で表示されます。

1. あなた宛の進行確認
2. 自分が出した進行確認
3. 今日のタスク

進行確認が終わったら「完了」を押します。

「返信文」を押すと、Chatworkなどに返すための返信フォーマットをコピーできます。

## 10. タスクの日付と完了

前日以前の未達成タスクは、アプリを開いたときに自動で今日のタスクへ繰り越されます。

繰り越されたタスクには「繰り越し」ラベルが付きます。

同じタスクが何度も増えないように、繰り越し元のタスクを記録しています。

完了したタスクは通常のタスク一覧から消えます。

ただし、データとしては残るため、「完了済みも表示」や日付範囲の指定で過去の実績として確認できます。

## 11. プロジェクトの納品日

プロジェクトの納品日は必須扱いです。

納品日が未入力のまま保存することもできますが、プロジェクト画面に「納期未設定」の警告が出ます。

納品日が不明な場合は「Chatwork文をコピー」を押して、担当者に確認文を送ります。

確認文には入力用URLが入ります。

担当者はURLからTaskBoardを開いて、プロジェクト編集画面で納品日を入力します。

納品日がわかったら、プロジェクト編集画面で入力します。

## 12. プロジェクト・フェーズ・タスクの関係

TaskBoardでは、次の順番で考えます。

```text
プロジェクト
  └ フェーズ
      └ タスク
```

プロジェクトは、納品物・案件・月号・キャンペーンなど、進行管理したい単位です。

フェーズは、そのプロジェクトの中の工程です。例：制作、確認、修正、提出。

タスクは、各メンバーが実際に作業する単位です。

基本ルール:

- タスクは必ず何らかのプロジェクトに紐づけます。
- フェーズは必須ではありません。未経験の案件や流動的な案件は、まずフェーズなしでタスクを積み上げても構いません。
- 一度終わった案件は、あとからフェーズとタスクを整理してテンプレート化します。
- フェーズは「管理したい工程」だけにします。細かすぎる作業はタスクにします。
- プロジェクトの窓口担当は、プロジェクト一覧のプルダウンで絞り込めます。

プロジェクト編集画面の主な項目:

- プロジェクト種別: 通常、定期、仮プロジェクトを選びます。
- 定期案件名: 定期案件の親シリーズ名です。
- プロジェクト名: 今回分の案件名です。
- クライアント名: 相手先・媒体名・案件元です。
- 窓口担当: 進行責任者です。
- 納品日: このプロジェクトの最終日付です。
- 進行状態: 進行中、保留、完了を選びます。
- プロジェクト備考: 案件全体の注意点だけを書きます。

## 13. フェーズの日付管理

フェーズを使う場合は、各フェーズに開始日と締切日を持たせます。

理由は、プロジェクト全体の納品日だけでは、どの工程が遅れているか見えにくいためです。

フェーズの日付は、ガント表示や進行状況の確認に使います。

フェーズに持たせる項目:

- フェーズ名
- 開始日
- 締切日
- 担当者
- 状態
- 実行条件

状態の例:

- 未着手
- 進行中
- 確認待ち
- 完了
- 保留

実行条件は、そのフェーズやタスクを始める前に必要な条件です。

例:

- プレゼント決定が完了していないと、LPデザイン制作に進めない。
- LPコーディングが完了していないと、テスト応募に進めない。
- クライアント確認が完了していないと、広告バナーを決定できない。

同時進行できるフェーズは、無理に順番で縛りません。

ただし、前工程が終わっていないと進めてはいけないフェーズには、実行条件を設定します。

## 14. ガント表示の考え方

ガント表示は、個人の今日のタスクを見るためではなく、プロジェクト全体の流れを俯瞰するために使います。

最初はタスク単位ではなく、プロジェクトとフェーズ単位で表示します。

理由は、タスクをすべてガントに出すと細かすぎて、全体の進行が見えにくくなるためです。

ガントで見たいこと:

- クライアント別に、進行中のプロジェクトが見える
- 定期案件ごとに、今月分・次回分の流れが見える
- 納品日が近いプロジェクトが見える
- 遅れているフェーズが見える
- 同時進行しているフェーズが見える
- 誰がどのフェーズを担当しているか見える

ガントの絞り込み:

- クライアント別
- 定期案件別
- 窓口担当別
- 担当者別
- 期間別
- プロジェクト種別別

ガントに必要な情報:

- クライアント名
- 定期案件名
- プロジェクト名
- プロジェクト開始日
- プロジェクト納品日
- フェーズ名
- フェーズ開始日
- フェーズ締切日
- フェーズ担当者
- フェーズ状態
- 実行条件

プロジェクト開始日と納品日だけでも大まかな表示はできます。

ただし、進行管理として使う場合は、フェーズごとの開始日と締切日が必要です。

## 15. ガント表示での運用ルール

プロジェクトを登録するときは、まず最低限の情報だけで登録できます。

最低限必要な情報:

- 登録者
- クライアント名
- プロジェクト名
- 窓口担当
- 納品日

フェーズがわかっている案件は、フェーズも登録します。

フェーズを登録する場合は、開始日と締切日も入力します。

まだフェーズが決まっていない案件は、フェーズなしで登録して構いません。

ただし、進行が見えてきたら、あとからフェーズを追加します。

不足している情報がある場合は、プロジェクト画面からChatwork確認文を送ります。

確認文には入力用URLを入れ、担当者が画面から情報を補完できるようにします。

## 16. 定期案件の考え方

定期案件名とプロジェクト名は、同じではありません。

定期案件名は、親になるシリーズ名です。

プロジェクト名は、今回進める個別案件名です。

例:

```text
定期案件名: 明治安田 月号
プロジェクト名: 7月号
クライアント名: 明治安田
納品日: 2026/06/20
```

この場合、「明治安田 月号」という定期案件の中に、「7月号」という今回分のプロジェクトがある、という扱いです。

納品日は、定期案件名ではなく、各プロジェクトに入れます。

理由は、同じ定期案件でも、月ごと・号ごとに納品日、フェーズ、担当者、窓口が変わることがあるためです。

Chatworkで `明治安田7月` や `丹平製薬7月` のような名前が来た場合は、アプリ側では定期案件の候補として扱います。

ただし、既存プロジェクトと完全一致しない場合は、自動で決め打ちせず、プロジェクト確認URLから既存プロジェクトに紐付けるか、新規プロジェクトとして作成します。

## 17. まずの運用ルール

- 毎日前日までに、各メンバーが `#task` を送ります。
- 進行に関わる確認がある場合だけ、同じ投稿に `#ask` を足します。
- 個人的な作業相談はTaskBoardに入れず、本人同士で直接確認します。
- 管理者は一括入力で貼り付け、「確認する」で内容を見てから登録します。
- プロジェクト未設定があれば、Chatwork文をコピーして本人に送ります。
- 既存プロジェクトと似ている名前がある場合は、プロジェクト確認URLから紐付けます。
- 本人は自分用URLから修正します。
- 未達成タスクは翌日に自動で繰り越されます。
- プロジェクトの納品日は必ず確認します。
