# TaskBoard 利用者マニュアル

更新日: 2026-06-26

## 1. TaskBoardで管理するもの

TaskBoardは、各メンバーの毎日のタスクと、案件全体の進行を見えるようにするためのツールです。

基本の考え方は次の通りです。

- タスクは、誰が、いつから、いつまでに、何時間分の作業をするかを表す単位です。
- 未完了のタスクは、翌日以降も今日のタスクとして表示されます。
- 未完了のタスクは、日付が変わっても同じタスクとして扱います。毎日新しいタスクが増えるわけではありません。
- タスクは、原則として必ずプロジェクトに紐付けます。
- プロジェクトは、案件・月号・キャンペーン・納品物など、進行を管理する単位です。
- フェーズは、プロジェクト内の工程です。必要な場合だけ使います。
- 確認・進行許可・修正は、期限と担当者を持つタスクとして管理します。
- 制作案件では、担当者ごとの1日8hを基準に、作業の重なり具合を確認します。

## 2. 毎日の使い方

各メンバーは、自分用URLからTaskBoardを開きます。

自分用URLで開くと、最初から自分のタスクを中心に確認できます。

毎日の基本作業は次の流れです。

1. タスクページを開く
2. 今日やるタスクを確認する
3. 終わったタスクにチェックを入れる
4. 新しいタスクがあれば登録する
5. 確認系タスクがあれば回答する

他の人がタスク取得や編集を行った直後は、画面右上またはタスク画面の「最新に更新」を押して、最新状態にしてください。

## 3. タスクの登録方法

タスクは、次の2つの方法で登録できます。

- アプリ画面から直接登録する
- ChatworkのTASK部屋から取り込む

### 画面から登録する場合

タスク画面で「タスク追加」または「一括入力」を使います。

入力する主な項目は次の通りです。

| 項目 | 内容 |
|---|---|
| 担当者 | 作業する人 |
| プロジェクト | タスクが属する案件 |
| フェーズ | 工程。未定なら「フェーズなし」で可 |
| 開始日 | そのタスクに着手する日 |
| 締切日 | その日までに終わらせる日 |
| タスク内容 | 実際にやる作業 |
| 予定時間 | 0.25時間単位 |
| 遂行期間（日） | 開始日から締切日までの営業日数 |
| 備考 | 補足、引き継ぎ、注意点 |

同じ情報は、どのページでも同じ値を見ます。たとえばプロジェクト名やクライアント名はプロジェクト側の情報を参照し、タスク側に別名でコピーして管理しません。タスクの締切日は締切日として保存し、今日のタスク画面に表示する日は別の表示日として扱います。

プロジェクトがまだ存在しない場合は、原則として登録する本人・窓口担当・佐久間さんが新規作成します。

### Chatworkから登録する場合

TASK部屋に `#task` を付けて投稿します。

基本フォーマット:

```text
6月12日
#task
プロジェクト名,タスク内容,予定時間,備考
プロジェクト名,タスク内容,予定時間,備考
```

例:

```text
6月12日
#task
明治安田 7月号,差し替え企画スポーツの原稿執筆→校正提出,2
パルシステム座談会WEB記事,広告バナー内容整理→出田さんに依頼,1,アップ後に内容確認
```

区切り文字は `,` と `/` のどちらも使えます。

同じプロジェクトのタスクが続く場合は、2行目以降のプロジェクト名を `+` にできます。

```text
6月12日
#task
A社サイト制作,トップページ修正,1
+,画像差し替え,0.5
```

プロジェクトが不明な場合は、先頭を `?` にします。

```text
#task
?,原稿確認,0.5,どの案件か確認が必要
```

ただし、`?` が多いとデータ整理が重くなるため、できるだけ既存プロジェクト名を使ってください。

Chatwork入力では締切専用の項目がないため、登録された作業日を仮締切として保存します。今日のタスクでは「締切 仮」と表示されるので、必要に応じてタスク編集で正式な締切日に直してください。

## 4. タスク完了の扱い

タスクにチェックを入れると、完了扱いになります。

完了したタスクは通常のタスク一覧からは消えますが、データとしては残ります。

間違えてチェックした場合に戻せるよう、画面上では一時的に表示されることがあります。別画面へ移動したあとや、翌日以降は通常表示から外れます。

完了チェック後、他の人の画面にすぐ反映されない場合は、その人が「最新に更新」を押してください。

## 5. 繰り越しタスク

昨日以前の未完了タスクは、日別表示日だけが今日へ移動され、今日のタスクとして表示されます。

締切日は「その日までに終わらせる日」として残ります。繰り越しによって締切日が勝手に今日へ変わることはありません。

元の日付が今日より前のタスクには「繰り越し」ラベルが付きます。

日付チップには、元の日付や「昨日」「5日前」「6/7〜今日」などが表示されます。

重要なルール:

- 繰り越しで新しいタスクは作りません。
- 1つのタスクの表示日だけが今日へ移動します。
- 元の日付は、いつから残っているタスクかを見るために保持されます。
- プロジェクトのタスク一覧でも、同じ繰り越しタスクを日ごとに何件も表示しません。

タスクが溜まっている場合は、次の可能性があります。

- 見積時間が甘い
- タスク量が多すぎる
- 優先順位が整理されていない
- プロジェクトの進行設計に無理がある
- 未完了理由が残っていない

朝会では、繰り越しが多い人や予定時間が多すぎる人を確認し、作業量を調整します。

## 6. 確認タスク

タスク登録・編集画面の「進行に関わる確認」欄は廃止しました。確認者と進行許可者はプロジェクト・フェーズで設定し、実際の確認作業は期限と担当者を持つ確認系タスクとして管理します。

テンプレートで確認工程が決まっている場合は、確認タスクも予定として最初から作成します。前工程が終わるまでは待機状態とし、作業完了時に確認可能へ切り替えて担当者へ通知します。

今日のタスクに出る「通知・お願い」は、確認作業そのものではなく知らせです。同じプロジェクト・同じ対象タスク・同じ宛先の通知は複数作成せず、カード内にプロジェクト名、対象タスク名、期限状態を表示します。

### ガントで工程を編集する

ガント画面の「工程を編集」を押すと、タスクの前提関係と日程を調整できます。

ガントの上部には月表示と日表示が並びます。月をまたぐ工程でも、どの月の作業かを確認できます。

1. ガント上の細いタスクバーを選ぶ
2. 「このタスクを始めるために完了が必要なタスク」を選ぶ
3. 必要に応じて、タスクだけまたは後続タスクも含めて1営業日ずつ移動する
4. 編集を終えたら「工程編集を終了」を押す

選択中のタスクは紫、前提タスクは黄、直後のタスクは緑で表示します。関係のないタスクは薄く表示するため、依存関係が増えても全体が線だらけになりません。

前提タスクが終わっていないタスクは開始待ちです。完了操作や確認回答をしようとすると、未完了の前提タスクが表示されます。

テンプレート編集の「直前完了後」を有効にしたタスクは、プロジェクト作成時に直前タスクの完了後に開始する設定になります。確認系タスクは初期状態で「直前完了後」が有効です。

タスク登録時は、次の種別から選びます。

| 種別 | 内容 |
|---|---|
| 作業 | 担当者が実際の制作・処理を行う |
| 依頼 | 他の担当者へ作業を依頼する |
| 修正 | 指摘内容を受けて成果物を直す |
| 納品 | 提出・公開・納品を実行する |
| 確認 | 作業内容が問題ないか見る |
| 進行許可 | 次工程へ進めてよいか判断する |

「作業・依頼・修正・納品」は作業系タスクです。「確認・進行許可」は新規登録できる確認系タスクです。「再確認」は修正タスクが完了したときに自動作成されます。

確認系タスクを選ぶと、締切日は翌営業日になります。都合により変更できます。

確認系タスクの回答:

| 回答 | 動作 |
|---|---|
| OK | 確認を完了する |
| 差し戻す | 理由・修正担当・修正期限を入力し、修正タスクを自動作成する |
| 保留 | 外部回答待ちなどの理由と、次の回答期限を設定する |

進行許可では「許可する / 許可しない / 保留」、再確認では「修正確認済み / 再差し戻し / 保留」と表示します。内部の状態は共通です。

### 確認が延びた場合の日程調整

確認の保留や差し戻しで予定が延びた場合、担当者が後続タスクの日付を一件ずつ変更する必要はありません。

1. システムがタスク間の空きをバッファーとして使用します
2. バッファー内に収まる場合、後続タスクの日付は変更しません
3. バッファーを超えた分だけ、未完了の後続タスクとフェーズ日程を自動調整します
4. 納品日は自動変更しません
5. 変更内容は進行管理役へ「日程変更」として通知されます
6. 納品日を超える見込みの場合、進行管理役へ警告します

通知には、変更原因、使用したバッファー、変更件数、移動日数、納品への影響が表示されます。

タスク日程は「開始日」「遂行期間（営業日）」「締切日」をまとめて入力します。開始日と遂行期間を入力すると、締切日を自動計算します。締切日を手で変更した場合は、入力済みの開始日は変更しません。

この日程はタスク画面、プロジェクトのタスク一覧、テンプレート展開、ガント、担当者別負荷で共通利用します。別画面を開いた際に、同じ日付を入力し直す必要はありません。

入力する項目:

| 項目 | 内容 |
|---|---|
| 誰に | 確認したい相手 |
| いつまでに | カレンダーで選ぶ回答期限 |
| 内容 | 確認したいこと |

例:

```text
誰に: 山田さん
いつまでに: 2026/06/25
内容: この画像で次工程へ進めてよいか確認してください
```

### 差し戻しが発生した場合

確認でNGになった場合は、元の作業タスクを未完了に戻さず、次のように扱うのがわかりやすい運用です。

1. 作業タスクは完了のまま残す
2. 確認タスクで「差し戻す」を選ぶ
3. 差し戻し理由を残す
4. 翌営業日期限の修正タスクが自動作成される。確認者は必要に応じて期限を変更する
5. 修正タスクが完了したら、翌営業日期限の再確認タスクが自動作成される
6. 再確認がOKなら、必要に応じて進行許可へ進む

この形にすると、「最初の作業は終わったが、確認後に追加修正が発生した」という履歴が残ります。

修正タスクは新しい予定時間を持つため、担当者の負荷にも自然に反映できます。

## 7. プロジェクトの扱い

プロジェクトは、タスクをまとめる親の単位です。

プロジェクトには、主に次の情報を入れます。

| 項目 | 内容 |
|---|---|
| 案件区分 | 既存クライアント / 提案系など |
| 案件流入元 | その案件がどこから来たか |
| 案件流入元詳細 | 紹介元、媒体名、フォーム名、代理店名など |
| プロジェクト種別 | 通常プロジェクト / 定期プロジェクト |
| クライアント名 | クライアント・媒体・案件元 |
| 定期案件名 | 定期案件の場合の親シリーズ名 |
| プロジェクト名 | 今回分の案件名 |
| 登録者 | プロジェクトを登録した人。新規作成時に自動で記録されます |
| 窓口担当 | 進行責任者 |
| 納品日 | 最終納品日 |
| 開始日 | ガント表示の開始位置 |
| 備考 | 案件全体の注意点 |

案件流入元は、今後どのチャネルを強化するかを判断するための情報です。

主な選択肢:

- 自社開発
- LPからの問い合わせ
- 自社HPからの問い合わせ
- 既存クライアントからの紹介
- 代理店からの案件
- メディアレーダー
- 既存クライアントからの追加依頼
- 営業・直接提案
- その他

案件流入元詳細には、わかる範囲で具体的に残します。

例:

```text
案件流入元: メディアレーダー
案件流入元詳細: ホワイトペーパー資料DL後の問い合わせ
```

通常プロジェクトでは、定期案件名は使いません。

定期プロジェクトでは、定期案件名が親シリーズ、プロジェクト名が今回分になります。

例:

| 項目 | 例 |
|---|---|
| 定期案件名 | プレゼントキャンペーン更新 |
| プロジェクト名 | 2026年7月切り替え |
| 納品日 | 2026/06/28 |

### プロジェクトテンプレートを使う場合

制作案件や定期案件では、テンプレートを使うと入力が楽になります。

基本の流れ:

1. プロジェクト追加を押す
2. 制作案件または定期案件のテンプレートを選ぶ
3. 納品日を入力する
4. 自動で作られたフェーズとタスクを確認する
5. 必要に応じて担当者、開始日、締切日、遂行期間、工数、内容を修正する
6. 登録する

テンプレートの標準タスクでは、納品日から逆算して締切日が入ります。

逆算は土日祝を除いた営業日で計算されます。

担当者が未設定の標準タスクは、プロジェクトの窓口担当が自動で担当になります。

### テンプレートを編集する場合

設定ページのテンプレート管理から編集できます。

標準タスクで編集できる項目:

| 項目 | 内容 |
|---|---|
| タスク名 | 作業内容 |
| フェーズ | どの工程に属するか |
| 種別 | 作業、依頼、確認など |
| 担当 | デフォルト担当。未設定なら窓口担当 |
| 営業日前 | 納品日から何営業日前に置くか |
| 遂行期間（日） | 開始日から締切日までの営業日数 |
| 工数 | 予定時間。担当者の日別負荷の集計に使います |

例:

| 営業日前 | 意味 |
|---|---|
| -10 | 納品日の10営業日前 |
| -1 | 納品日の1営業日前 |
| 0 | 納品日当日 |
| 5 | 納品日の5営業日後 |

標準タスクが多いテンプレートは、編集モーダル内でスクロールできます。

### プロジェクトを削除する場合

プロジェクトを削除すると、そのプロジェクトに紐付いているタスクも一緒に削除されます。

関連する「確認・お願い」も削除されます。

削除前に、関連タスク数と確認・お願いの件数が表示されます。

完了した案件を履歴として残したい場合は、削除ではなく「完了」または「アーカイブ」を使ってください。

## 8. 新規プロジェクト作成のルール

プロジェクトの乱立を防ぐため、新規プロジェクトを作成してよい人を限定します。

新規作成してよい人:

- 佐久間さん
- その案件の窓口担当
- その案件の登録者

それ以外のメンバーは、原則として既存プロジェクトを選びます。

既存プロジェクトが見つからない場合は、勝手に新規名を作らず、`?` を使って確認待ちにします。

## 9. データ整理

データ整理ページでは、次の内容を確認・修正します。

- 未紐付け・確認待ちタスク
- 仮プロジェクト
- クライアント名の表記ゆれ
- 繰り越し不整合
- 不足情報のあるプロジェクト
- 重複タスク

同じ担当者・同じ内容・同じプロジェクト・同じ予定時間のタスクが複数ある場合は、整理対象として確認します。

重複タスクでは、候補タスクの内容、日付、完了状態を確認してから統合できます。

完了済みのタスクが混ざっている場合も、候補一覧を開いて確認できます。

仮プロジェクトは、正式プロジェクトへ統合するか、不要ならアーカイブまたは削除します。

ただし、紐付いているタスクが全て完了済みの仮プロジェクトは、整理対象として表示されません。

紐付いているタスクがない仮プロジェクトは、削除判断が必要なため表示されます。

クライアント名に「京急」と「京浜急行」のような表記ゆれがある場合は、正式名称へ統合します。

## 10. ガント

ガントページでは、プロジェクトとフェーズの流れに加えて、担当者ごとの混み具合を確認できます。

主な使い方:

- クライアント別に見る
- 定期案件別に見る
- 窓口担当別に見る
- 担当者別に見る
- プロジェクト種別で見る

担当者別の混み具合では、各タスクの予定時間を、開始日から締切日までの営業日に按分します。

表示の目安:

| 状態 | 意味 |
|---|---|
| 8h超過 | その日の作業量が基準を超えている |
| 6h以上 | 混み合っている |
| 0〜4h程度 | まだ余力がある可能性がある |

新規プロジェクトを立ち上げるときは、テンプレートから生成されたタスクを担当者に割り当て、ガントで赤い日が増えすぎていないか確認します。

赤い日が多い場合は、担当者、開始日、締切日、遂行期間、工数を調整します。

完了プロジェクトは、原則として通常表示から外します。

納品日未設定や遅れ気味のプロジェクトは、警告表示の対象になります。

## 11. 困ったとき

### 自分の画面と他の人の画面が違う

「最新に更新」を押してください。

### 登録したタスクやプロジェクトが消えないか確認したい

画面左下の保存状態を確認してください。

- 「サーバー保存済み」: 登録内容はサーバーへの保存と照合が完了しています
- 「サーバーへ保存中」: 保存処理中です
- 「サーバー保存待ち」: 通信回復後に自動で再保存します。保存済みになるまで画面を閉じないでください

未送信の登録内容が端末に残っている場合、次にアプリを開いたときはサーバー上の古い内容で上書きせず、端末の未送信内容を先にサーバーへ保存します。

### タスク追加画面で新しいプロジェクトも登録したい

「このタスク用にプロジェクトを作成」を開き、プロジェクト情報を入力して、画面下の「追加する」を押してください。プロジェクトの作成、テンプレートの標準タスク作成、入力中のタスク登録を一度に行います。「作成して紐付け」を先に押す操作はありません。

### チェックしたタスクが戻っている

保存に失敗した可能性があります。通信状態を確認し、再度チェックしてください。

### Chatworkから取り込まれない

次を確認してください。

- `#task` が入っているか
- TASK部屋に投稿しているか
- 投稿者のChatworkアカウントIDがメンバーに登録されているか
- プロジェクト名、タスク内容、時間が入っているか

### プロジェクトが多すぎる

データ整理ページで、仮プロジェクトや重複クライアントを整理してください。

## タスク種別と締切の登録ルール

タスク追加時は、最初にタスクの扱いを選びます。

- プロジェクト作業: 案件・納品物・クライアントに関わる作業です。プロジェクトを選びます。
- 自己完結タスク: 日次作業や社内作業など、本人だけで完了できる作業です。プロジェクトは不要です。
- 確認してもらう作業: 作業後に誰かの確認が必要な作業です。確認者と確認締切を入れると、確認者の画面に確認タスクが自動で出ます。
- 待ち・追いかけ: クライアント待ち、外部素材待ち、社内確認待ちなど、自分が追いかける責任を持つものです。待ち先、理由、次回確認日を入れます。

締切日は必須です。まだ正式な締切が決まっていない場合は「この締切は仮」を選び、仮締切理由と次回確認日を入れてください。
